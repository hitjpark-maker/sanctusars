# 매일 포스팅 자동 제작

매일 **한국 시간(Asia/Seoul) 오전 4시 30분**에 그날의 복음과 특별 주제를 조사한다. 주제 선택을 기다리지 않고 확인된 각 주제의 짧은 글과 이미지 A/B/C를 제작·검수해 함께 제시한다. 실제 게시를 자동 실행하는 기능은 아니다.

## 처음 내려받은 사용자의 예약 설정

이 저장소를 Codex에서 열고 다음과 같이 요청한다.

> 이 저장소의 workflows/daily-topics.md에 따라 매일 한국 시간 오전 4시 30분에 이 대화에서 복음과 해당하는 특별 주제의 글·이미지 제작까지 진행하도록 예약해줘.

Codex는 앱의 예약 도구로 현재 대화에 연결된 예약을 생성한다. 같은 목적의 기존 예약이 있으면 갱신하고 중복 생성하지 않는다. 아래 실행 지침을 읽도록 예약 프롬프트에 저장소 위치와 이 문서 경로를 넣는다. 시간대와 활성 상태를 확인한다. 예약 도구가 없으면 설정 완료라고 말하지 않는다.

**git pull은 제작 지침과 도구를 가져오며 앱의 예약 자체를 설치하지 않는다.** 각 사용자는 자신의 앱에서 한 번 예약을 설정해야 한다. 개인 예약 ID, 대화 ID, 계정 설정은 Git에 넣지 않는다. 로컬 파일을 사용하는 예약은 컴퓨터와 앱이 실행 중이고 저장소에 접근 가능해야 한다. 실제 무인 실행과 사용량은 각 환경에서 확인한다.

## 예약 실행 지침

1. 최신 AGENTS.md, README.md, brand/style.md, brand/editorial.md를 읽는다. 한국 날짜를 YYYY-MM-DD로 확정한다. 늦게 실행되었다면 실제 실행 시각을 기록하고 예정 시각에 실행했다고 주장하지 않는다.
2. 주교회의 해당 날짜 매일미사의 날짜·전례일·복음 구역·장절을 직접 읽고 전례력 및 굿뉴스의 날짜별 자료와 대조한다. 복음의 핵심 주제를 짧게 정한다. 검색 요약이나 전년도 자료로 대체하지 않는다. 재전재 자료를 독립 원문 검증으로 과장하지 않는다.
3. 주요 전례일과 대축일·축일·기념일, 잘 알려진 성인의 기념 날짜를 확인한다. 성인의 날짜·생애·핵심 의미는 공식 가톨릭 자료로 확인한다. 한국 전례력, 지역·수도회 고유 거행, 성인 기념 날짜를 구분한다. 유명하다는 이유로 전례 등급을 높이지 않는다. 복음 한 건은 매일 제작한다. 주요 전례일과 잘 알려진 성인 주제가 있으면 각각 독립 제작하여 보통 두세 건을 제시한다. 같은 대상을 중복 제작하지 않으며 특별 주제가 없으면 복음 한 건만 제작한다. 특별 주제는 관련성이 높은 최대 두 건을 고르고 선정 이유를 기록한다. 공동 축일은 한 건으로 묶는다.
4. output/YYYY-MM-DD/daily-topics/에 조사 기록을 새 버전으로 보존한다. 실제 조회 시각, 출처 URL, 직접 확인한 내용, 확인 범위·접근 실패, 전례 등급, 복음 선택지, 추천 이유를 적는다. 각 번호와 절대 날짜·제작 종류·대상·미사 구분·장절을 연결한다. 기존 제작 건이나 승인을 덮어쓰지 않는다. 같은 날짜의 실제 준비 알림이 이미 있고 변경이 없으면 중복 알리지 않는다.
5. **조사 → 즉시 제작 → 글과 그림 제시**를 기본으로 한다. 사용자는 확인된 복음과 특별 주제의 자동 제작을 사전 요청했다. 번호·주제명 선택이나 시작 승인을 다시 받지 않는다. 이 사전 요청은 이미지 선택·최종 승인은 아니다. 선택창, 버튼, codex-followup 안내를 넣지 않는다.
6. 평소에는 주교회의 해당 날짜 기본 미사의 복음을 사용한다. 선택 기념일의 대안 본문이 있다는 이유만으로 기본 복음 제작을 멈추지 않는다. 서로 다른 미사나 본문 중 기본값을 확정할 수 없는 실제 미해결 선택은 임의로 결정하지 말고 해당 건만 보류하고 필요한 선택을 텍스트로 알린다. 다른 검증 완료 건은 계속 제작한다. 자료 불일치·접근 실패가 해결되지 않은 건도 생성하지 않는다.
7. 각 제작 건의 status를 확인하고 기존 작업을 재개하거나 독립 생성한다. 같은 job을 동시에 수정하지 않는다. 최신 AGENTS.md의 검증·evidence/check·짧은 본문·prepare·내장 도구를 통한 실제 이미지 A/B/C 생성·시각 검수를 그대로 따른다. 주제 선정만으로 멈추거나 프롬프트를 이미지 대신 제시하지 않는다. 특별 포스팅은 별도 occasion job으로 기록한다. 성인 주제는 이 자동 제작 요청을 사전 제작 지시로 기록하되 사용자가 개별 성인을 선택한 문구를 만들어내지 않는다.
8. 결과는 **복음 글 → 복음 이미지 A/B/C → 특별 포스팅 글 → 해당 이미지 A/B/C** 순서로 주제별 묶어 제시한다. 두 건이면 실제 이미지 여섯 장, 세 건이면 아홉 장이다. 짧은 본문은 준비된 파일 그대로 제시한다. 그림 선택·수정·최종 승인 절차는 유지한다. 예약 시각은 제작 시작 시각이며 완료 시각을 보장하지 않는다.
9. 동일 날짜의 완료된 제작은 다시 생성하지 않는다. 일부만 끝났으면 성공한 글·이미지를 보존하고 미완료 건만 재개한다. 도구나 사용량 제한으로 중단하면 완료·미완료 범위를 알린다. 자동 추가 결제·모델 하향 전환·외부 이미지 API·실제 게시·예약 게시·자동 Git push는 하지 않는다.

## 수동 테스트

“2026년 10월 12일 새벽 4시 30분이라고 가정하고 준비해줘. 테스트야.”처럼 요청할 수 있다. 실제 출처를 조회하되 mode를 manual_schedule_test로, 가정한 시각과 실제 조회 시각을 별도로 기록한다. 테스트 요청이 조사까지만인지 실제 제작까지인지 요청 범위를 따른다. 테스트 자체를 실제 예약 실행·발송 완료나 이미지 선택·최종 승인으로 세지 않는다. 이후 실제 예약 실행의 중복 방지에도 포함하지 않는다.

현재 확인 범위: 2026년 10월 10일과 12일의 주제 조사와 안내를 수동 테스트했다. 이전 선택 UI는 사용자 화면에 나타나지 않았다. 이후 사용자의 명시적 요청으로 선택 대기 없이 각 주제를 자동 제작하는 방식으로 변경했다. 이 테스트는 새벽 무인 실행이나 다른 사용자 환경의 예약 성공을 검증한 것이 아니다.
