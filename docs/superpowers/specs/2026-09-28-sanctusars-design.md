# SanctusArs 제작 시스템 설계

상태: 2026-09-28 사용자 방향 승인. 구현 계획 작성 단계. 화풍·로고·서체의 실제 자산 승인은 별도다.

## 목적과 확정 요구사항

매일의 가톨릭 복음을 성화, 묵상, 부담 없이 답할 수 있는 질문으로 전하여 공감과 자발적인 나눔, 반복 참여가 있는 신앙 문화를 만든다.

- GitHub 저장소를 받아 다른 사람도 동일한 SanctusArs 제작 흐름을 사용한다. 브랜드 교체 기능은 제공하지 않는다.
- AI 작업은 ChatGPT 또는 Codex 안에서 수행한다. 외부 AI 서비스와 수동 외부 이미지 제작은 요구하지 않는다.
- 이미지 생성은 시스템의 필수 실행 단계다. 프롬프트만 출력하는 것은 제작 완료가 아니다.
- 성화 시안 세 개를 만들고 사용자가 선택한다.
- 요청 날짜의 정확한 복음만 사용한다. 날짜·전례일·미사 구분·복음 검증을 통과하기 전에 이미지와 글을 생성하지 않는다.
- 성인의 축일과 중요한 전례일에는 매일 복음 포스팅 외에 그날을 위한 별도 포스팅을 제공한다.
- 성화는 신비로움, 사실성, 회화적 질감, 독특한 표현과 높은 디테일 완성도를 지향한다.
- 자동 게시는 구현하지 않는다. 사용자 확인 후 게시용 결과를 출력하고 사용자가 직접 게시한다.
- 로고 및 핵심 문구를 담는 말씀카드를 검토한다. 실제 로고 자산, 서체와 최종 배치는 아직 승인되지 않았다.

## 첫 버전의 구현 제안

Codex에서 저장소를 열고 자연어로 제작을 요청하는 파일 기반 작업 흐름으로 시작한다. 별도 웹 앱, 데이터베이스, 자체 AI 서버는 만들지 않는다. ChatGPT 단독 실행과 모든 Codex 환경에서의 호환성은 첫 버전의 보장 범위에 포함하지 않는다.

현재 세션에서 제공되는 내장 이미지 생성 도구를 사용한다. 저장소 복제만으로 해당 도구의 접근 권한까지 생기는 것은 아니다. 실행 시작 시 이미지 생성 기능을 확인하고, 사용할 수 없으면 작업을 중단하고 필요한 실행 환경을 안내한다. 외부 AI나 별도 API 경로로 자동 전환하지 않는다.

## 제작과 승인 흐름

1. 아래 날짜·전례 검증 절차를 완료한다. 검증된 복음과 기념일 자료를 분리하여 매일 복음 제작 건과 필요한 특별 제작 건을 만든다.
2. 복음에서 핵심 의미 하나와 이를 드러낼 행동·감정·장면을 정한다. 인용문과 창작 묵상은 구분한다.
3. 같은 복음과 SanctusArs 화풍을 유지하는 A/B/C 시안을 각각 별도 이미지로 생성한다. 각 후보의 차이는 구도, 시점, 빛, 감정 표현으로 만든다.
4. 세 이미지를 실제로 검토하고 비교 화면과 차이 설명을 제시한다. 사용자는 A/B/C 선택, 수정 요청, 전부 재생성 중 하나를 지정한다. 추천은 가능하지만 시스템이 선택을 대신하지 않는다.
5. 선택한 후보를 기준으로 수정한다. 선택된 원본은 보존하며 새 버전을 만든다. 다른 후보로 몰래 교체하지 않는다.
6. 완성된 성화와 일치하는 묵상, 기도, 캐주얼한 질문, 채널별 본문과 말씀카드 문구를 구성한다.
7. 승인된 브랜드 자산으로 로고와 문구를 별도 조판한다. 초기 로고 파일이 없으면 임의의 공식 로고를 만들지 않고 자산 제공을 요청한다. 브라우저나 로컬 조판 도구는 AI 생성 서비스와 구분되는 보조 도구다.
8. 최종 이미지와 글 전체를 보여 준다. 사용자의 명시적 최종 승인 이후에만 승인된 게시용 묶음을 출력한다. 게시 작업은 수행하지 않는다.

시안 선택은 최종 게시물 승인이 아니다. 승인 후 이미지나 글을 수정하면 최종 승인을 다시 받아야 한다. 사용자 응답이 없으면 승인 대기 상태를 유지한다.

## 날짜·복음 검증: 생성 전 필수 조건

- 기본 전례력은 한국 천주교, 날짜 기준은 Asia/Seoul로 제안한다. ‘오늘/내일’은 실행 시점의 한국 날짜를 바탕으로 YYYY-MM-DD로 확정해 먼저 표시한다. 컴퓨터의 현지 시간대나 SNS 게시 시각에서 전례 날짜를 추정하지 않는다. 명시한 제작 날짜와 실제 게시 예정 시각은 따로 저장한다.
- 한국천주교주교회의 매일미사의 해당 날짜 본문을 우선 출처로 사용한다. URL에 날짜가 있다는 이유만으로 통과시키지 않고 본문의 연·월·일, 전례일 이름, 미사 구분, 복음 책과 장절, 복음 본문을 읽는다. 검색 결과 요약이나 기억만으로 확정하지 않는다. 복음 환호송의 성경 구절을 복음으로 잘못 읽지 않는다.
- 요청 날짜와 본문 날짜를 일치 검사한다. 주교회의 전례력과 전례일을 대조한다. 가톨릭 공식 보조 자료를 이용해 동일 날짜·동일 미사 구분의 복음 범위를 교차 확인한다. 보조 자료가 원출처를 재전재한 경우 독립된 증거로 과장하지 않는다.
- 연도별 이동 축일, 한국 전례력의 이동 거행, 우선순위 및 기념일 선택은 해당 연도 공식 자료를 따른다. 단순한 월일 목록이나 AI의 연도 계산으로 공식 자료를 대체하지 않는다. 특정 교구·본당 고유 전례는 별도 공식 근거가 있어야 적용한다.
- 전야·밤·새벽·낮 미사, 긴/짧은 복음과 선택 기념일의 독서 등 복수 선택지가 있으면 출처에서 확인된 선택지와 차이를 제시한다. 성탄 등 여러 미사 양식에 임의의 하나를 적용하지 않는다. 사용자의 기존 선택이 없다면 해당 제작 건의 미사 양식을 확인받고 기록한다. 다음 실행에서도 다른 날짜·다른 미사의 본문을 섞지 않는다.
- 원문 인용은 선택된 복음 본문과 대조한다. 장절뿐 아니라 인용 문장도 맞아야 하며, 생략·발췌는 드러내고 창작 묵상과 구분한다. 전례 원문 전체를 공개 Git 저장소에 일괄 재배포하지 않는다.
- 출처 URL, 확인 시각, 요청 날짜, 본문 날짜, 전례일, 미사 구분, 복음 장절, 확인한 인용과 교차 확인 결과를 제작 기록에 저장한다. 최종 미리보기에도 날짜·전례일·미사 구분·복음·출처를 확인할 수 있게 한다.
- 날짜 불일치, 출처 간 충돌, 누락, 접근 실패, 미사 선택 미확정이면 검증 보류로 남기고 이미지·본문 제작을 시작하지 않는다. 근처 날짜나 전년도 자료로 조용히 대체하지 않는다. 검증은 오류 가능성을 줄이는 절차이며 절대 무오류를 보장하는 것으로 표현하지 않는다.
- 제작 도중 날짜·미사 양식·복음이 바뀌면 연결된 이미지와 글을 재검토하고 이전 검증과 승인을 무효화한다.

## 축일·기념일 특별 포스팅

매일 복음 제작 건은 항상 유지한다. 특별 포스팅은 별도 이미지와 별도 글로 제공하며 그날 복음을 다른 본문으로 바꾸는 방식으로 처리하지 않는다.

기본 편집 범위 제안은 한국 공식 전례력에 기재된 대축일·축일·의무 기념일·선택 기념일 및 성주간과 부활 등 주요 전례일이다. 전 세계 모든 성인을 매일 나열하지 않는다. 같은 날 선택 기념일이 여럿이면 모두 후보로 알리고 특별 포스팅 대상 성인을 선택받는다. 실제 거행 전례와 선택 가능한 성인 기념을 구분해 표기하며, 공식 전례력에 없는 추가 기념 대상은 사용자의 요청과 신뢰할 교회 자료가 있을 때만 포함한다.

특별 포스팅은 기념 대상의 정확한 이름과 등급, 해당 연도 거행 날짜, 의미, 성인의 경우 확인된 생애와 도상적 상징, 짧은 묵상·기도·질문을 담는다. 교회 공식 자료를 우선하며 출처 없는 명언·생애 일화·기적을 만들어 넣지 않는다. 전승과 확인된 사실을 구분한다.

각 특별 제작 건에도 시안 세 개 → 사용자 선택 → 수정·조판 → 최종 승인 흐름을 적용한다. 매일 복음과 특별 포스팅의 선택·승인은 독립적이다. 예를 들어 대축일에 제작 건 두 개가 있으면 각각 시안 세 개를 제공한다. 승인 대기 중인 특별 포스팅 때문에 검증과 승인이 끝난 매일 복음 결과를 잃지 않는다.

## 화풍 확정과 일일 시안의 구분

첫 스타일 탐색에서는 같은 장면으로 빛과 붓질의 정도가 다른 세 후보를 비교한다. 사용자 선택과 수정으로 기준 작품을 확정한다. 이후 매일의 세 후보는 고정 화풍 안에서 장면 연출을 달리하며, 매일 서로 다른 화풍을 경쟁시키지 않는다.

화풍의 잠정 기준:

- 인물은 설득력 있는 인체, 손, 시선, 옷의 무게를 갖춘다.
- 얼굴의 섬세한 묘사와 옷·배경의 붓질이 자연스럽게 공존한다.
- 신비로움은 빛, 그림자, 공간과 여백으로 표현한다. 과도한 광선이나 효과가 기본값이 되지 않게 한다.
- 의미 없는 장식보다 그날 복음을 드러내는 몸짓과 사물을 우선한다.
- 기준 작품과 색채·질감·인물 표현을 비교하되 모든 장면에 같은 배경과 조명을 강요하지 않는다.

## 품질 검수

각 후보는 복음과의 연결, 인체와 손, 시선, 의복과 사물의 논리, 회화적 질감, 브랜드 일관성, 작은 화면에서의 중심 장면을 점검한다. AI 검토는 보조 수단이며 사용자의 판단을 대체하지 않는다. 숫자 점수를 전문가 수준의 증명으로 사용하지 않는다.

묵상은 구체적인 일상 경험과 복음을 연결한다. 질문은 정답이나 민감한 자기 고백을 요구하지 않으며 매일의 주제에 맞게 작성한다. 직접 성경 인용에는 장절을 붙이고 창작 문장을 성경 인용처럼 표기하지 않는다.

자동 재생성은 무한 반복하지 않는다. 후보에 명백한 결함이 있으면 해당 후보를 한 차례 수정하고, 해결되지 않으면 문제와 이미지를 사용자에게 보여 준다. 일부 생성이 실패하면 성공한 후보를 보존하며 세 후보가 준비되기 전에는 시안 단계가 완료됐다고 표시하지 않는다.

## 저장소 구성 제안

- README.md: 설치·실행 환경·제작 요청 예시·승인 절차.
- AGENTS.md: 단계별 실행 지침, 승인 경계, 브랜드 유지 규칙.
- brand/: 승인된 화풍 지침, 사용 권한을 확인한 기준 이미지·로고·글꼴.
- templates/: 장면 설계, 생성 지시, 묵상, 검수와 카드 조판의 공통 양식.
- scripts/: 필요한 최소한의 조판·내보내기 도구. 이미지 생성을 흉내 내는 대체 구현은 두지 않는다.
- output/: 날짜별 후보, 선택·수정 이력, 본문, 최종 산출물. 일일 산출물은 기본 Git 추적에서 제외한다.

작업 기록에는 날짜, 전례력, 복음 출처와 인용, 생성 지시, 후보 경로, 선택 후보, 수정 버전, 승인 대상과 승인 상태를 남긴다. 원본을 덮어쓰지 않고 중단 후 승인 대기 단계에서 재개할 수 있게 한다. 기록은 이미지가 완전히 동일하게 재생성된다는 보장을 뜻하지 않는다.

## 완료 기준과 검증

- 깨끗한 복제본에서 문서만 따라 제작을 시작할 수 있다. 내장 이미지 생성 사용 가능 여부를 시작 단계에서 확인한다.
- 실제 이미지 파일 세 개가 생성·표시되고 사용자 선택 전에는 후속 완성 단계로 넘어가지 않는다.
- 시안 선택과 최종 승인이 별도로 기록된다. 승인 후 수정은 기존 승인을 무효화한다.
- 중단 후 재개해도 선택한 후보와 원본이 보존된다.
- 성경 인용과 창작 묵상이 구별되고, 출력 파일의 한글·로고·여백을 실제 렌더링으로 확인한다.
- 외부 AI 호출과 자동 게시가 없다.
- 잘못된 날짜의 페이지, 연도 오류, 한국 날짜 경계, 복음 환호송 오인, 이동 거행, 복수 미사 양식, 출처 불일치·장애가 검증 보류로 처리되는지 확인한다. 성탄과 성모 승천 대축일은 해당 연도 공식 자료로 실제 검증한다.
- 기념일 없는 날은 매일 복음만, 대상 기념일에는 별도 특별 제작 건을 제공한다. 복수 성인 선택과 두 제작 건의 독립적인 승인을 확인한다.
- 승인 상태에 관한 구현에는 작은 실행 가능한 검증을 남긴다. 실제 내장 생성·사용자 선택·출력 흐름은 한 회차의 종단 간 실행으로 확인한다.

## 범위 밖과 남은 결정

다중 브랜드, 외부 AI 연동, 자동 게시, 예약 실행, 성과 수집 대시보드는 첫 버전에서 제외한다.

실제 시안 비교로 화풍과 기준 작품을 확정해야 한다. 로고 원본과 재배포 권한, 글꼴 라이선스, 카드 규격과 배치는 구현 전 해당 단계에서 확인한다. 공개 저장소의 코드 라이선스와 브랜드·성화 자산의 사용 조건은 구분하여 사용자가 결정한다. 저장소를 공개하는 행위 자체는 이 설계 승인에 포함되지 않는다.
